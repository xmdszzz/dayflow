Chat Context — 滑动窗口 + 记忆压缩机制

消息生命周期 · 滑动窗口 · 每日压缩 · 长期记忆

🔄 消息生命周期

① Active
滑动窗口内 · 完整保留
最近 20 轮对话
→
② Stale
超出窗口 · 折叠显示
"6月3日对话 · 添加了3个任务"
→
③ Archived
每日 0:00 自动压缩
摘要存入长期记忆表
→
④ Memory
按日期检索
注入系统 prompt 提供上下文

📐 核心规则

机制 规则 说明
滑动窗口 保留最近 20 轮对话
超出部分折叠为摘要行		 20 轮足够覆盖一天的高频使用
发送第 21 条时自动折叠最早的一轮
过期任务清理 任务时间 < 当前时间 → 自动折叠
任务状态 = done/cancelled → 3天后折叠		 聊天记录中引用的已发生任务
显示为灰色折叠条，不占上下文
每日压缩 每天 0:00 或应用启动时触发
压缩昨天的 Active+Stale → 摘要		 LLM 生成摘要：日期、添加的任务数、
修改/删除、关键事件关键词
长期记忆 摘要存入 memory 表
用户新消息时注入相关记忆		 "你上周三跟张总开过评审会"
"这个月你已经加了15个会议"

📋 SQLite 新增表

chat_messages & chat_memory
-- 聊天消息表（持久化存储，支持折叠/归档）
CREATE TABLE chat_messages (
  id         TEXT PRIMARY KEY,       -- UUID
  role       TEXT NOT NULL,          -- 'user' | 'assistant' | 'system'
  content    TEXT NOT NULL,          -- 原始消息内容
  tool_calls TEXT,                 -- JSON: LLM 返回的 function_call
  status     TEXT NOT NULL DEFAULT 'active',  -- active|stale|archived
  date_tag   TEXT NOT NULL,          -- '2026-06-04' 所属日期
  created_at TEXT NOT NULL
);

-- 长期记忆表（每日压缩摘要）
CREATE TABLE chat_memory (
  id         TEXT PRIMARY KEY,       -- UUID
  date       TEXT NOT NULL UNIQUE,  -- '2026-06-04'
  summary    TEXT NOT NULL,          -- LLM 生成的摘要
  task_count INTEGER NOT NULL,      -- 当天操作的任务数
  keywords   TEXT,                 -- JSON: ["评审","预算","健身"]
  created_at TEXT NOT NULL
);

🔄 运行时流程

Context Builder — 每次 sendMessage() 触发
function buildContext(userMessage) {

  // 1. 从 SQLite 取最近 20 条 status=active 的消息 (滑动窗口)
  const activeMessages = db.getActiveMessages(20);

  // 2. 取过期消息的折叠摘要行 (status=stale, 只取摘要不取全文)
  const staleSummary = db.getStaleSummary();  // "更早的对话中，你添加了5个任务..."

  // 3. 取最近 7 天的长期记忆摘要 (按日期近→远)
  const recentMemories = db.getMemories(7);

  // 4. 取未发生的未来任务 (提供时间上下文)
  const upcomingTasks = db.getUpcomingTasks();

  // 5. 组装 messages 数组发给 DeepSeek
  return [
    { role: 'system', content: systemPrompt + recentMemories },
    { role: 'system', content: '未来任务：' + upcomingTasks },
    ...staleSummary,                     // 折叠的摘要作为 system
    ...activeMessages,                   // 最近 20 条原样保留
    { role: 'user',   content: userMessage },
  ];
}

⏰ 每日压缩触发时机

触发点 1
应用启动时
检查昨天是否有未压缩的 active/stale 消息
有则调用 LLM 生成摘要 → 存入 memory → 原消息标记 archived
触发点 2
定时器 (每小时检查)
Main Process 的 ReminderService 顺带检查
如果跨天了 + 有未压缩消息 → 触发压缩
触发点 3
滑动窗口溢出时
第21条消息写入时
最早的一轮对话被标记为 stale
（stale 是中间态，等压缩时统一归档）
